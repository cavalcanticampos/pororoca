Roadmap

Five milestones. Each one has a test for "done" that a stranger could run. The full plan lives in the PRD.

M1

Core, CLI and a fleet you can try in minutesdone

  • maloca.yaml loader and pororoca maloca check
  • Card store (SQLite), pipeline, fail-closed gatekeeper, autonomy levels, chaser
  • pororoca doctor: checks Claude Code, gh login, folders and limits
  • pororoca init with presets (solo-dev, tech-lead, founder)
  • pororoca demo: a fake inbox, no GitHub or Slack, cards closed in about two minutes
  • Local inbox, GitHub forge and GitHub Issues adapters
  • CI-aware landing: red CI goes back to the builder, green CI merges within the merge autonomy level, and the judge reads the diff
  • Fleet-editable allowlist: the fleet grants itself a narrow tool, the judge approves

Done when: A solo fleet fixes a real GitHub issue end to end, from the terminal only. Reached on 2026-11-18: issue to triage, gatekeeper, investigation, PR, green CI, judge-approved merge and closed issue in about two minutes, with no human step.

M2

Slack adapter and shadow modenext

  • Read what is addressed to you, reply as you (signed 🤖) or as a bot
  • A week in shadow mode produces the "would have resolved without you" report

Done when: The shadow report earns each autonomy level with evidence.

M3

Onboarding measured with real peopleplanned

  • Starter maloca polished from M1 feedback
  • Guided init for chat and tracker adapters

Done when: A new user reaches M1 in under 30 minutes, measured with 3 people.

M4

Jirau, the cockpitplanned

  • A Claude Code pane next to your chat
  • Priorities on top, your lane, and the real state of each open card

Done when: The pane shows the lane and the priorities, with real states.

M5

Jira, Linear and team modeplanned

  • Tracker adapters for Jira and Linear
  • Several humans share one maloca, each with their own lane

Done when: Two humans share one maloca.

Patterns from the reference fleet

The private fleet Pororoca comes from learned these the hard way. They move into the core as generic features, with nothing tied to the company that ran it.

Weekly-limit pauseWhen the runtime hits its usage limit, the whole fleet pauses and requeues work instead of dumping it on you.
Fail-closed gatekeeperIf the gatekeeper cannot judge a card, the card waits. It never falls into your lane by default.
Work claimsBefore building, the fleet checks who is already on it: open PRs, recent merges and manual claims ("someone is on it").
Technical-failure retryA git error, a crashed session or a timeout is retried on its own. It is the fleet's problem, not yours.
Additive-migration judgeA new table or a nullable column is safe; a drop is not. The judge tells them apart instead of flagging every migration.
Per-repo decision memoryWhat you decided about a repo is written down once and read by every agent that touches it.
Human takeoverWhen you type in a conversation, the fleet steps back for 24 hours. A stop emoji ends its part; a new emoji opens a fresh card.
Promises become tasks"I'll send it at 3pm" turns into a scheduled task, so a promise made on your behalf is kept.
Skill smithA procedure that shows up in three or more reports becomes a reusable skill.
CI sentinelA red default branch becomes a card on its own, grouped so one failure is one card.
Video proofAfter a change reaches staging, the fleet records the screen doing the thing.
Daily retroThe fleet reads your corrections every day and fixes itself. The metric: times the human corrected the fleet this week.
Fleet-editable allowlistThe fleet may widen its own tool permissions, with every change reviewed by the judge.
Watcherspororoca doctor --watch keeps an eye on cost, disk, stalled routines and denied tool calls.
