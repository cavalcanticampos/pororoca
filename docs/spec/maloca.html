maloca.yaml

One file declares the team: who the agents are, when they run, who chases whom, what each one may do alone, and where things escalate.

version: "0.2"            # OpenRig RigSpec version
name: my-fleet
pods:
  - id: flow
    members:
      - { id: gatekeeper,  runtime: claude-code }
      - { id: triage,      runtime: claude-code }
      - { id: investigator, runtime: claude-code }
      - { id: builder,     runtime: claude-code }
      - { id: deliverer,   runtime: claude-code }
      - { id: chaser,      runtime: claude-code }
x-maloca:
  mode: solo                     # solo | team
  humans: [{ id: ana, address: ana@external }]
  gatekeeper: flow.gatekeeper    # the only door to a human lane
  schedules: { triage: "*/2 * * * *", chaser: "*/10 9-18 * * 1-5" }
  autonomy:                      # propose | judge | alone
    reply.routine: propose
    pr.open: alone
    pr.merge.sensitive: judge
  chase: { people: off, after: 24h, escalate_after: 2d }
  shadow: true

Compatibility with OpenRig

Underneath, the file is an OpenRig RigSpec v0.2 (pods, members, edges). There is one catch: today the RigSpec rejects unknown keys at every level, so a file with x-maloca does not load in OpenRig as is.

  • pororoca export --openrig writes a plain rig.yaml without the extension.
  • We will propose upstream that the RigSpec accept and keep x-* keys.

Checks

pororoca maloca check fails when:

  • the running fleet differs from the file;
  • any card state has no chaser;
  • an agent can reach a human lane without going through the gatekeeper.
