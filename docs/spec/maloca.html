maloca.yaml

One file declares the team: who the agents are, when they run, who chases whom, what each one may do alone, and where things escalate.

This is the file pororoca init --preset solo-dev writes. Hover or tap a highlighted key to see what it does.

version: "0.2"  # OpenRig RigSpec version
name: my-fleet  # your fleet name
pods:  # OpenRig: groups of members
  - id: core
    members:  # one entry per agent session
      - id: gatekeeper
        runtime: claude-code  # the only runtime in v0.1
      - { id: triage,       runtime: claude-code }
      - { id: investigator, runtime: claude-code }
      - { id: builder,      runtime: claude-code }
      - { id: deliverer,    runtime: claude-code }
      - { id: chaser,       runtime: claude-code }
edges: []  # OpenRig: who talks to whom
x-maloca:  # Pororoca extension block
  mode: solo  # solo | team
  humans:  # the people the fleet works for
    - id: me
      name: Your Name
      github: your-handle
  agents:  # member id -> name, role, schedule
    gatekeeper:   { name: Guaraná,  role: gatekeeper }
    triage:       { name: Curupira, role: triage, schedule: "*/5 * * * *" }
    investigator: { name: Boto,     role: investigator }
    builder:      { name: Boitatá,  role: builder }
    deliverer:    { name: Uirapuru, role: deliverer }
    chaser:       { name: Iara,     role: chaser, schedule: "*/10 * * * *" }
  autonomy:  # propose | judge | auto (or human, off)
    reply: propose
    open_pr: auto
    merge: judge
    sensitive_change: human  # CI config, migrations, infra, secrets
    chase_people: off
  chase:  # when and how often to nudge
    waiting_on_person: { after: 60m, every: 30m, max: 4 }
    waiting_on_pr: { after: 2h, every: 2h, max: 3 }
  escalation:  # what may reach you
    to: me
    only_for: [credential, money, personal, product_conflict, irreversible_prod]

x-maloca

Everything Pororoca adds lives here. OpenRig rejects unknown keys today, so pororoca export --openrig writes a copy without this block.

Compatibility with OpenRig

Underneath, the file is an OpenRig RigSpec v0.2 (pods, members, edges). There is one catch: today the RigSpec rejects unknown keys at every level, so a file with x-maloca does not load in OpenRig as is.

  • pororoca export --openrig writes a plain rig.yaml without the extension.
  • We will propose upstream that the RigSpec accept and keep x-* keys.

Checks

pororoca maloca check fails when:

  • the running fleet differs from the file;
  • any card state has no chaser;
  • an agent can reach a human lane without going through the gatekeeper;
  • there is not exactly one gatekeeper, or sensitive_change is set to auto.
