Adapter contracts

Each port has a small interface. Where OpenRig already has a contract, Pororoca uses the same shape, so an OpenRig adapter is a thin translation.

Conversation

One interface covers both Slack, which replies as you, and the local CLI inbox. "Speaks as you" is a capability flag, not a separate design. The envelopes follow OpenRig's Relay gateway v1: eventId, deliveryId, replyRef, intent and outcome, in push or pull mode.

export interface ConversationPort {
  readonly connectorRef: string;
  readonly caps: { replyAsHuman: boolean; threads: boolean; edit: boolean;
                   retract: boolean; mode: "push" | "pull" };
  fetch(cursor?: string): Promise<{ events: InboundEvent[]; cursor: string }>;
  send(msg: Outbound): Promise<Receipt>;   // the core adds the " 🤖" signature
  ack?(deliveryId: string): Promise<void>; // pull mode: the inbox confirms custody
  edit?(r: Receipt, text: string): Promise<Receipt>;  // feeds the embarrassment metric
  retract?(r: Receipt): Promise<void>;
  link(ref: ThreadRef | Receipt): string;
}
export interface Outbound {
  deliveryId: string; to: ThreadRef | Address; text: string;
  as: "human" | "bot";               // "human" requires caps.replyAsHuman
  intent: "decision" | "update"; outcome?: "interrupt" | "notify" | "digest";
  replyRef?: string;
}

Forge and tracker

export interface ForgePort {
  readonly caps: { checks: boolean; autoMerge: boolean };
  openPR(i: { repo: string; branch: string; title: string; body: string; cardId: string }): Promise<{ id: string; url: string }>;
  status(prId: string): Promise<{ state: "open" | "merged" | "closed";
    checks: "pending" | "pass" | "fail"; review: "none" | "changes" | "approved" }>;
  comment(prId: string, text: string): Promise<void>;
  merge?(prId: string): Promise<void>;
}
export interface TrackerPort {
  fetch(cursor?: string): Promise<{ items: TrackerItem[]; cursor: string }>;
  setState(externalId: string, s: CardState, note?: string): Promise<void>;
  comment(externalId: string, text: string): Promise<void>;
}
// the same states as an OpenRig queue item
export type CardState = "pending" | "in-progress" | "blocked" | "done"
  | "failed" | "denied" | "canceled" | "handed-off";
Rule: a card waiting on a person outside the fleet is blocked on that person and is never done. Closing on hand-off is how open work goes silent.

Humans and runtime

Humans follow OpenRig's human registry: an @external address, connector bindings with a secrets reference, and availability. The agent runtime follows OpenRig's harness and runner contract (working, idle, or needs input; exact resume or a clear failure), and its conformance check is our test.
